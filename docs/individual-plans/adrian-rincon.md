# Adrian Rincon’s Individual Development Roadmap

## Suggested starting theme: structured problem discovery

Use this as a hypothesis to validate in your kickoff conversation. The aim is to turn an ambiguous request into a clear problem statement, evidence, and a useful next-step recommendation.

### 30-day outcome

> I will improve structured problem discovery by framing one real challenge with users, constraints, assumptions, and success measures. I will know it is useful when a reviewer can decide on a next step from my one-page brief.

| Week | Practice | Evidence |
| --- | --- | --- |
| 1 | Select a real challenge and write a one-sentence problem statement. | Problem brief and three assumptions. |
| 2 | Ask three discovery questions of a relevant stakeholder or peer. | Notes grouped into patterns. |
| 3 | Compare two possible approaches and their trade-offs. | Decision matrix or sketch. |
| 4 | Present a recommendation and request focused feedback. | Final brief plus reviewer comment. |

## Weekly reflection

- What did the evidence challenge or confirm?
- Which assumption needs to be tested next?
- Can I state the decision I need from others in one sentence?

## Evidence checklist

- [ ] A clear problem statement
- [ ] Stakeholder or user input
- [ ] Assumptions and constraints made visible
- [ ] A recommendation with trade-offs
- [ ] Feedback and an updated next step
